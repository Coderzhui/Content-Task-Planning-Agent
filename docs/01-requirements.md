# 需求理解

| 项目 | 定义 |
|---|---|
| 用户 | 需要在预算与截止时间内产出内容活动方案的运营人员 |
| 价值假设 | 把「素材/工具选型 + 成本/耗时约束」的决策交给 Agent，减少人工试错；尚未测量真实业务收益 |
| 输入 | 主题、预算、截止时间（可用工时 `deadline_hours`）、素材/工具费用与耗时表 |
| 输出 | 任务计划、步骤状态、工具结果、费用合计、已保存方案（或未完成原因） |
| 范围 | 本地 CLI、合成素材/工具目录、ReAct 决策循环、状态管理、成本/耗时估算、幂等方案保存 |
| 不包含 | 真实线上部署、多 Agent、生产级 Runtime、真实联网检索、界面、真实创意/合规审查 |
| 业务工具 | 素材检索、脚本生成、成本估算、方案保存（本地确定性实现，可注入失败） |
| 模型 | 双入口：真实 LLM（OpenAI 兼容，DeepSeek 已实跑）+ 离线确定性 Mock（默认） |

## 成功标准（验收点 → 预期）

| 验收点 | 预期状态 | 关键判定 |
|---|---|---|
| 正常完成 | `completed` | 在预算与截止内保存方案 |
| 缺预算/截止时间 | `needs_input` | 列出缺失字段 |
| 工具失败 | 调整/重试后完成或明确停止 | 失败步骤不记为成功，已成功步骤保留 |
| 预算超限 | 改选更便宜方案 | 估算 12 → 改选 8 → `completed` |
| 重复执行 | 结果一致 | 幂等 plan_id |
| 无可行方案（参考实例延伸） | `incomplete` | 返回未完成及缺口原因 |

## 效果边界

- 离线 Mock 只验证流程与状态机制，**不构成真实 ReAct 决策证据**；真实决策效果需接入真实模型后验证。
- 素材/工具为合成数据，脚本为模板占位，不评估真实创意与合规质量。
